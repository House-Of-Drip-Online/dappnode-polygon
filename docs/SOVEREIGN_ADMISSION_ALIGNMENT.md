## Project role

Infrastructure dependency boundary only. Node/deployment infrastructure is not automatically an admitted autonomous system and does not inherit application-level Sovereign authority.

## Governing alignment

This repository remains an independent project and build boundary. Nothing in Sovereign alignment merges this repository with MAEVN Holdings, Sovereign Protocol, APEX variants, SYMEN, ATA, Asset Hunter, or any other project.

The trust/admission sequence is:

```text
PRE-SOVEREIGN / UNADMITTED
  -> SOVEREIGN PROTOCOL
  -> REGISTER / CANON / EVIDENCE
  -> VALIDATE
  -> EVALUATE
  -> REMEDIATE / REVALIDATE when required
  -> CERTIFY
  -> VALUE
  -> CONVERGENCE LOCK
  -> ADMISSION GRANT
  -> AUTHORIZED UMBRELLA PARTICIPATION
  -> CONTINUOUS SURVEILLANCE
```

## Core rules

- **No Convergence Lock -> No Sovereign Admission.**
- **Valid Convergence Lock + Active Admission -> Authorized ecosystem access only within exact certified scope.**
- Convergence Lock is immutable version truth.
- Admission state is current operational authority and may be ACTIVE, SUSPENDED, REVOKED, or EXPIRED.
- A material new version requires a new Sovereign examination, new lock, and new admission decision.
- Registration, ownership, common organization, common infrastructure, payment, or prior certification do not equal current admission.
- Cross-system access is deny-by-default and requires current locks/admission for both sides plus certified compatible interfaces and permissions.

## API / interface rule

Interfaces that cross Sovereign boundaries must be declared before lock issuance when part of the certified manifestation. Admission activates only the interface versions and permissions represented by the applicable lock.

## Separation law

This project retains its own:
- Canon and technical truth
- repository and source authority
- build/release identity
- deployment/infrastructure
- secrets and security boundary
- runtime/evidence ledger
- product/commercial boundary

Alignment is achieved through registry IDs, evidence, certificates, Convergence Locks, Admission states, and certified interfaces — never by silently merging repositories or builds.

## Conflict rule

If local documentation conflicts with SOV-ADM-001 on trust/admission semantics, SOV-ADM-001 controls the shared Sovereign admission relationship. Local project Canon continues to control this project's internal technical behavior unless explicitly amended through its own Canon authority process.
